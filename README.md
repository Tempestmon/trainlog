# trainlog

Журнал тренировок в git: форма для телефона пишет подходы и вес в CSV через GitHub API, а `trainlog` считает тренд веса, советует по питанию и следит за прогрессом в базовых упражнениях.

```
program.json          сплит, упражнения, диапазоны повторов, шаги прогрессии, блоки сезона
data/lifts.csv        подходы: date,session,exercise,set,weight_kg,reps,rir
data/body.csv         утренний вес: date,weight_kg,waist_cm,sleep_h,note
form/                 статическая форма (index.html + logic.js + app.js), без сборки и зависимостей
src/trainlog/         CLI аналитики (только стандартная библиотека; matplotlib — опционально)
.github/workflows/    ci: тесты и валидация данных; weekly-report: отчёт по воскресеньям; pages: деплой формы
```

## Как это работает

1. Открываешь форму, выбираешь «3 / 4 дня» и тренировку (Ноги A, Верх A, …).
2. Форма читает `program.json` и `data/lifts.csv` из репозитория и подставляет веса: прошлый результат из той же тренировки плюс шаг прогрессии.
3. Вписываешь повторы и запас, жмёшь «Сохранить». Форма дописывает строки в CSV и делает коммит `chore(log): legs_a 2026-10-22`.
4. На каждый коммит CI прогоняет `trainlog check`. Если в данные попало что-то битое, придёт письмо о падении.
5. В воскресенье в 20:00 (Екатеринбург) workflow `weekly-report` кладёт отчёт в Summary запуска: Actions → weekly-report → последний запуск.

### Правила подсказок в форме

- **Топ + добивочные** (присед, жим): если в топ-подходе сделан верх диапазона с запасом ≥ `rir_min`, то вес + `increment_kg`; иначе тот же вес. Добивочные подходы — 90% от топа, округление вниз до 2,5 кг.
- **Прямые подходы**: все подходы на верхней границе диапазона → + `increment_kg`. Если в последнем подходе запас ≥ 5, шаг удваивается. Иначе тот же вес.
- История берётся из той же тренировки (сгибания в Ногах A и B идут с разными весами), если её нет — из любой.
- Повторная отправка той же тренировки за ту же дату заменяет её, перед этим форма спрашивает подтверждение.
- Пока данные не ушли в репозиторий, ввод хранится как черновик в браузере и переживает закрытие вкладки.

### Правила отчёта

- Тренд веса — наклон линейной регрессии за 14 дней (нужно ≥ 5 взвешиваний на отрезке ≥ 7 дней), в кг/нед.
- Питание: < 0,2 — добавить ~250 ккал; 0,2–0,5 — без изменений; > 0,5 три недели подряд и талия +1 см за 3 недели — урезать. Первые 14 дней сезона решений нет.
- e1RM по Эпли: вес × (1 + повторы/30). «Застой» — две последние тренировки не превысили ту, что была перед ними.
- Пороги лежат в `program.json → nutrition`.

## Установка

### 1. Репозиторий

```sh
git remote add origin git@github.com:<you>/trainlog.git
git push -u origin main
```

### 2. Где жить форме

Форма — три статических файла. Данные она получает через API с токеном, поэтому сама страница ничего не содержит.

- **Публичный репозиторий + GitHub Pages.** Settings → Pages → Source: GitHub Actions, workflow `pages` задеплоит `form/`. Минус: CSV с весами и подходами видны всем.
- **Приватный репозиторий.** На бесплатном плане Pages для приватных репозиториев недоступен. Форму можно положить на свой сервер как статику, например `caddy file-server --root form --listen :8080` за TLS. Workflow `pages` в этом случае просто отключи.
- **Два репозитория.** Публичный — с кодом и Pages, приватный — с `program.json` и `data/`. В настройках формы указывается приватный. Минус: CI и отчёт придётся настроить в приватном репозитории.

### 3. Токен

GitHub → Settings → Developer settings → Fine-grained tokens → Generate:

- Repository access: **Only select repositories** → `trainlog`;
- Permissions: **Contents: Read and write**, больше ничего;
- Expiration: на сезон, например до конца июня.

### 4. Телефон

Открой форму → вкладка «Настройки» → владелец, репозиторий, ветка `main`, токен → «Сохранить и проверить». Потом в меню браузера: «Добавить на главный экран».

## Безопасность

- Токен хранится в `localStorage` браузера. Его может прочитать любой JS с того же origin. У GitHub Pages все сайты пользователя живут на одном origin `<you>.github.io`, поэтому не держи там чужой или непроверенный JS. Своя статика на отдельном (под)домене изолирует форму полностью.
- Токен ограничен одним репозиторием и правом на содержимое: при утечке под угрозой только журнал.
- Внешних скриптов, CDN и аналитики в форме нет. `referrer` отключён.

## Forgejo / Gitea

В настройках формы есть поле API (`https://api.github.com` по умолчанию). Contents API у Forgejo устроен так же (GET с `?ref=`, PUT с `sha`), так что для переезда на свой Forgejo должно хватить смены адреса на `https://git.example.com/api/v1`. На Forgejo это пока не проверялось.

## CLI

```sh
pip install -e ".[plot,dev]"
trainlog check                         # валидация program.json и CSV, ошибки с номерами строк
trainlog report                        # отчёт за 7 дней до сегодня
trainlog report --date 2026-11-01 --out week3.md
trainlog plot --out-dir reports        # bodyweight.png, e1rm.png (нужен matplotlib)
```

## Разработка

```sh
pytest -q            # аналитика
npm ci && npm test   # логика формы и smoke-тест страницы на jsdom
```

Чтобы добавить упражнение, допиши его в `program.json` (`id`, `name`, `sets`, `reps`, `increment_kg`; для топа — `scheme: top_backoff` и `backoff`). `"track": true` выводит упражнение в таблицу e1RM, `"variants": [3]` показывает его только в варианте на 3 дня.
